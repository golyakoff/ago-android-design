Готовые ответы

Библиотека шаблонов, которые оператор вставляет в поле ввода вместо того, чтобы печатать заново (в треде их открывает «/»). Список + FAB + отдельный экран-редактор — вместо десктопной «пустой строки снизу», которая не работает с экранной клавиатурой. Открывается из Ещё → Автоматизация, только у обладателя site:configure.

Ловушка целого списка (PUT всей библиотеки)

У готового ответа нет идентификатора — сервер хранит всю библиотеку одним значением на сайте и заменяет её целиком. Любое изменение — добавить, отредактировать, удалить — это правка списка в памяти и один PUT всего списка, после чего состояние пересеивается из ответа сервера, а не из запроса. Порядок сохраняется, потому что его задал оператор, а не потому что он что-то значит: с этим списком ничего не сопоставляется (в отличие от «Автоответа вне смены», где порядок — это поведение).

01

Список и пустое состояние

Каждая строка — заголовок и превью текста; тап открывает редактор. FAB добавляет новый ответ. Загрузка и ошибка чтения — общие тела LoadingBody / RefusalBody.

02

Редактор — отдельный экран

Заголовок (одна строка, до 100) и текст (много строк, до 8000) со счётчиками. Сохранение отправляет весь список и пересеивает состояние из ответа сервера. У существующего ответа внизу — «Удалить» с подтверждением.

Крайние случаи

  • Два оператора правят одновременно. PUT всего списка — «последний победил», как и в консоли (у этого значения нет версии). Пересев из ответа сервера хотя бы показывает выжившему оператору настоящее сохранённое состояние.
  • Отказ сервера (CannedResponse.Invalid) показывается дословно, редактор остаётся открытым.
  • Проверка на клиенте — любезность, не власть: заголовок ≤ 100, текст ≤ 8000, ≤ 50 ответов; настоящий арбитр — UpdateCannedResponsesHandler.
